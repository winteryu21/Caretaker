# 인터렉티블/인과 오브젝트 Inspector 설정 매뉴얼

이 문서는 맵 디자이너가 씬 또는 프리팹 오브젝트에 조사, 획득, 아이템 사용, 일반 조작, 인과 조작을 연결하는 방법을 설명합니다. Interaction과 Causal은 실제 배치에서 같은 오브젝트 흐름으로 검수해야 하므로 기존 인터렉티블 매뉴얼에 함께 정리합니다.

관련 구현:

- `Caretaker/Assets/_Project/Scripts/World/InteractableObject.cs`
- `Caretaker/Assets/_Project/Scripts/World/OperateAction/IOperateAction.cs`
- `Caretaker/Assets/_Project/Scripts/World/OperateAction/DoorOperateAction.cs`
- `Caretaker/Assets/_Project/Scripts/World/OperateAction/RoomTransitionOperateAction.cs`
- `Caretaker/Assets/_Project/Scripts/World/OperateAction/PuzzleOperateAction.cs`
- `Caretaker/Assets/_Project/Scripts/World/CausalRuleSO.cs`
- `Caretaker/Assets/_Project/Scripts/World/CausalTrigger.cs`

- `Caretaker/Assets/_Project/Scripts/Gameplay/Player/InteractionProbe.cs`

## 1. 실전 요약

플레이어가 직접 만지는 오브젝트에는 `Interactable Object`를 붙이고, `Interaction Types`로 좌클릭 조사/획득 또는 `E` 조작 여부를 정합니다. 조작이 문 열기, 이동, 퍼즐 UI 열기처럼 현재 오브젝트에서 바로 끝나면 같은 GameObject에 `Door Operate Action`, `Room Transition Operate Action`, `Puzzle Operate Action` 같은 실행 컴포넌트를 붙입니다. 조작 결과가 다른 시간대의 오브젝트를 바꿔야 하면 조작 오브젝트에는 `Causal Trigger`를, 실제로 바뀌는 미래 오브젝트에는 `Causal Receiver`를 붙이고 둘 다 같은 `CausalRuleSO`를 연결합니다. 마지막으로 Persistent 씬의 `Causality Manager > Causal Rules` 배열에도 그 `CausalRuleSO`가 들어 있는지 확인합니다.

## 2. 빠른 연결표

| 만들 대상 | 붙일 컴포넌트 | 핵심 설정 |
| --- | --- | --- |
| 조사 가능한 안내문, CCTV, 책장 | `Interactable Object` | `Interaction Types: Examine`, `Examine Text/Image` 입력 |
| 줍는 아이템 | `Interactable Object` | `Interaction Types: Acquire`, `Grant Item ID` 연결 |
| 아이템을 써야 열리는 대상 | `Interactable Object` + 필요 시 OperateAction | `Required Item ID` 연결, 성공 후 `Operate`가 있으면 자동 실행 |
| 일반 문/버튼 | `Interactable Object` + `Door Operate Action` | `Interaction Types: Operate`, `Target Door` 연결 |
| 계단/엘리베이터 | `Interactable Object` + `Room Transition Operate Action` | `Destination`, `Target Room Id`, `Room Manager` 연결 |
| 퍼즐 장치 | `Interactable Object` + `Puzzle Operate Action` | `Puzzle Root` 연결, UI는 시작 시 비활성 |
| 과거 조작으로 미래를 바꾸는 레버/패널 | `Interactable Object` + `Causal Trigger` | `Interaction Types: Operate`, `Causal Rule` 연결 |
| 인과 결과로 바뀌는 미래 문/전등/플랫폼 | `Causal Receiver` | 같은 `Causal Rule` 연결, `On Activated/On Deactivated` 설정 |

## 3. 상세 설정

### 3.1 공통 Interactable Object

1. Hierarchy에서 플레이어가 감지해야 하는 GameObject를 선택합니다.
2. GameObject의 Layer를 플레이어 `Interaction Probe > Interactable Layers`에 포함된 Layer로 지정합니다.
3. `Interactable Object`를 추가합니다. `Circle Collider 2D`가 자동으로 추가되고 `Is Trigger`가 켜집니다.
4. `Circle Collider 2D`의 `Radius`와 `Offset`을 플레이어가 클릭하거나 접근할 영역에 맞춥니다.
5. `Object Identity > Item ID`에 이 오브젝트의 고유 ID를 가진 `ItemDefinitionSO`를 연결합니다. 예: `ItemId = OBJ_P1_BREAKER_PANEL`.
6. `Interaction Types`에서 필요한 타입을 선택합니다. 여러 타입을 함께 선택할 수 있습니다.
7. 조사, 획득, 아이템 조건에 필요한 필드를 입력합니다.
8. `Operate` 대상이면 같은 GameObject에 `Causal Trigger` 또는 하나 이상의 OperateAction 컴포넌트를 붙입니다.

감지용 Collider와 `Interactable Object`는 같은 GameObject에 있어야 합니다. 현재 감지 코드는 Collider가 붙은 GameObject에서 직접 `InteractableObject`를 찾습니다.

### 3.2 Interactable Object 필드

| Inspector 필드 | 설정 방법 |
| --- | --- |
| `Item ID` | 오브젝트 식별용 `ItemDefinitionSO`를 연결합니다. 이 SO의 `ItemId`가 런타임 `ObjectId`가 됩니다. |
| `Interaction Types` | `Examine`, `Acquire`, `Operate`, `UseItem` 중 지원할 타입을 선택합니다. |
| `Grant Item ID` | `Acquire` 성공 시 인벤토리에 추가할 `ItemDefinitionSO`를 연결합니다. |
| `Required Item ID` | 우클릭 아이템 사용에 필요한 `ItemDefinitionSO`를 연결합니다. 필요 없으면 비웁니다. |
| `Is Destroy` | `Acquire` 성공 후 오브젝트를 비활성화해야 할 때 켭니다. |
| `Examine Text` | `Examine` 성공 시 팝업 본문에 표시할 설명을 입력합니다. |
| `Examine Image` | 조사 팝업에 표시할 `Sprite`를 선택합니다. 비우면 텍스트 영역이 넓게 표시됩니다. |
| `Outline Behaviours` | 하이라이트 시 켜고 끌 아웃라인/강조 컴포넌트를 연결합니다. |
| `Use Fallback Glow` | 별도 아웃라인이 없어도 자식 `SpriteRenderer` 기반 glow를 자동 생성합니다. |

`Item ID`, `Grant Item ID`, `Required Item ID`는 모두 `ItemDefinitionSO` 참조입니다. 문자열을 직접 적는 칸이 아니라, SO 안의 `ItemId` 문자열을 시스템이 읽는 구조입니다.

### 3.3 Interaction Types와 입력

| 타입 | 입력 | 용도 |
| --- | --- | --- |
| `Examine` | 반경 안에서 좌클릭 | 안내문, CCTV, 책장, 잠긴 문 조사 |
| `Acquire` | 반경 안에서 좌클릭 | 신문, 배터리, 케이블 등 획득 |
| `Operate` | 반경 안에서 `E` | 문, 버튼, 레버, 엘리베이터, 계단, 퍼즐 장치 조작 |
| `UseItem` | 아이템 선택 후 대상에서 우클릭 | `Required Item ID` 조건 충족 |

좌클릭은 마우스를 올린 대상이 `Acquire` 가능하면 획득을 먼저 시도하고, 아니면 `Examine`을 시도합니다. `E`는 근접 대상의 `Operate`만 실행합니다. 우클릭 아이템 사용은 `Required Item ID`가 있고 아직 충족되지 않은 대상에서만 처리됩니다.

Tab 키로 전투 모드가 켜져 있으면 좌클릭/우클릭은 전투 입력으로 예약됩니다. 상호작용 연결을 테스트할 때는 일반 모드인지 확인합니다.

### 3.4 기본 유형 예시

조사 오브젝트:

```text
Interactable Object
  Item ID: SO_OBJ_P1_CCTV (ItemId = OBJ_P1_CCTV)
  Interaction Types: Examine
  Required Item ID: 비움
  Grant Item ID: 비움
  Examine Text: 엘리베이터가 작동하지 않는다.
```

획득 아이템:

```text
Interactable Object
  Item ID: SO_OBJ_P1_BATTERY_PICKUP (ItemId = OBJ_P1_BATTERY_PICKUP)
  Interaction Types: Acquire
  Grant Item ID: SO_ITEM_BATTERY (ItemId = ITEM_BATTERY)
  Is Destroy: 켬
```

아이템이 필요한 오브젝트:

```text
Interactable Object
  Item ID: SO_OBJ_P2_CARD_READER (ItemId = OBJ_P2_CARD_READER)
  Interaction Types: Operate
  Required Item ID: SO_ITEM_KEY_CARD (ItemId = ITEM_KEY_CARD)
  Examine Text: 카드키가 필요하다.
```

아이템 사용 흐름은 다음 순서로 진행됩니다.

```text
슬롯 키 1~5로 아이템 선택
→ 대상 반경 안에서 우클릭
→ Required Item ID와 선택 아이템 ID 비교
→ 성공 시 대상의 아이템 조건 충족 표시
→ 대상이 Operate를 지원하면 RunInteraction(Operate) 실행
```

대상에 `Causal Trigger`가 함께 붙어 있으면 아이템 사용 성공 뒤 인과 요청도 발생할 수 있습니다. 아이템 사용은 조건만 충족하고, 인과 요청은 별도 입력에서만 발생해야 하는 대상이라면 `Causal Trigger`를 다른 조작 오브젝트로 분리합니다.

### 3.5 일반 Operate 실행 컴포넌트

`Operate`는 `Interactable Object`와 같은 GameObject에 붙은 `Causal Trigger`와 모든 `IOperateAction` 구현 컴포넌트를 실행합니다.

```text
InteractableObject.RunOperate()
├─ CausalTrigger가 있으면 Fire()
└─ 같은 GameObject의 모든 IOperateAction.Execute(actor)
```

현재 제공하는 실행 컴포넌트:

| 컴포넌트 | 용도 | 필수 연결 |
| --- | --- | --- |
| `Door Operate Action` | 문 Animator 실행과 통행 Collider 비활성화 | `Target Door` |
| `Room Transition Operate Action` | 계단/엘리베이터 이동 | `Destination`, `Target Room Id`, `Room Manager` |
| `Puzzle Operate Action` | 퍼즐 UI 루트 활성화 | `Puzzle Root` |

`Operate`를 선택했지만 `Causal Trigger`와 OperateAction이 모두 없으면 상호작용은 실패합니다. OperateAction은 `Interactable Object`와 같은 GameObject에 붙여야 합니다.

문 또는 문 버튼:

```text
Door Button
├─ Interactable Object
│  └─ Interaction Types: Operate
└─ Door Operate Action
   └─ Target Door: 실제 문 GameObject
```

`Door Operate Action`은 `Target Door`와 자식에서 `Animator`와 첫 번째 비-Trigger `Collider2D`를 찾습니다. Animator에는 bool 파라미터 `IsOpen`이 있어야 합니다.

계단 또는 엘리베이터:

```text
Stair Interaction
├─ Interactable Object
│  └─ Interaction Types: Operate
└─ Room Transition Operate Action
   ├─ Destination: 도착 위치 Transform
   ├─ Target Room Id: 도착 룸 ID
   └─ Room Manager: Persistent 씬의 RoomManager
```

퍼즐 장치:

```text
Puzzle Device
├─ Interactable Object
│  └─ Interaction Types: Operate
└─ Puzzle Operate Action
   ├─ Puzzle Root: 비활성 상태로 시작하는 퍼즐 UI 루트
   ├─ On Puzzle Opened: 선택 사항
   └─ On Puzzle Closed: 선택 사항
```

닫기 버튼의 `OnClick`에는 `PuzzleOperateAction.Close()`를 연결합니다.

### 3.6 CausalRuleSO 준비

`CausalRuleSO`는 트리거와 리시버를 이어 주는 데이터입니다. 이미 준비된 SO가 있으면 새로 만들지 말고 그 SO를 사용합니다. 새 규칙이 필요하면 `Create > Caretaker SO > Causality > CausalRule`로 만듭니다.

| 필드 | 의미 | 예시 |
| --- | --- | --- |
| `Rule Id` | 규칙 자체의 ID | `CR_P1_POWER_PANEL` |
| `Trigger Id` | 트리거 오브젝트가 발화할 ID | `TRG_P1_POWER_PANEL` |
| `Required Role` | 이 규칙을 실행할 수 있는 플레이어 시간대 | `Past` |
| `Required Item Id` | Host 판정에서 필요한 아이템 ID | `ITEM_KEY_CARD` |
| `Conditions` | 퍼즐 상태 같은 추가 조건 | `breakerCombination = Correct` |
| `Receiver Effects` | 바뀔 리시버와 상태값 목록 | `RCV_P1_POWER_LIGHTS, powerState = Powered` |
| `Interaction Weight` | Major/Minor 진행 여부 | `Major` 또는 `Minor` |

`Trigger Id`는 `Causal Trigger`에 자동 표시되고, `Receiver Effects`의 `Receiver Id`는 `Causal Receiver`에 자동 표시됩니다. 같은 규칙이 여러 미래 오브젝트를 바꾸면 `Receiver Effects`를 여러 개 만들고, 각 미래 오브젝트의 `Causal Receiver`에서 자기 효과를 선택합니다.

### 3.7 Causal Trigger 설정

`Causal Trigger`는 보통 과거 플레이어가 직접 조작하는 레버, 패널, 버튼에 붙입니다.

1. 조작 오브젝트에 `Interactable Object`를 추가합니다.
2. `Interaction Types`에 `Operate`를 포함합니다.
3. 같은 GameObject에 `Causal Trigger`를 추가합니다.
4. `Causal Trigger > Causal Rule`에 해당 `CausalRuleSO`를 연결합니다.
5. Inspector에 표시되는 `Trigger ID`, `Required Role`, `Required Item`, `Weight`를 확인합니다.
6. 로컬 애니메이션이나 효과가 필요하면 같은 GameObject에 OperateAction을 추가합니다.

예시:

```text
Past Breaker Panel
├─ Interactable Object
│  ├─ Item ID: SO_OBJ_P1_BREAKER_PANEL
│  └─ Interaction Types: Examine, Operate
└─ Causal Trigger
   └─ Causal Rule: SO_CR_P1_POWER_PANEL
      └─ Trigger ID: TRG_P1_POWER_PANEL
```

`Causal Trigger`는 `Fire()` 호출 시 Persistent 씬의 `Causality Manager`에 ServerRpc 요청을 보냅니다. `Required Role`이 `Past`인 규칙을 미래 플레이어가 발화하면 Host에서 거부됩니다.

퍼즐 성공이 인과를 발화해야 하는 경우에는 퍼즐 UI의 성공 처리에서 연결된 `Causal Trigger.Fire()`가 호출되어야 합니다. 현재 `PuzzleUIBase`를 쓰는 퍼즐은 `_solvedTrigger` 슬롯에 해당 `Causal Trigger`를 연결하는 방식입니다.

### 3.8 Causal Receiver 설정

`Causal Receiver`는 인과 결과로 실제 상태가 바뀌는 오브젝트에 붙입니다. 보통 미래 시간대의 문, 전등, 플랫폼, 장애물, 통행 Collider가 대상입니다.

1. 바뀔 오브젝트 또는 그 제어용 GameObject를 선택합니다.
2. `Causal Receiver`를 추가합니다.
3. `Causal Rule`에 트리거와 같은 `CausalRuleSO`를 연결합니다.
4. 규칙에 `Receiver Effects`가 하나면 `Receiver ID`가 자동 표시됩니다.
5. 규칙에 `Receiver Effects`가 여러 개면 `Receiver Effect` 드롭다운에서 이 오브젝트에 해당하는 항목을 선택합니다.
6. `On Activated`에 인과 성공 시 실행할 동작을 연결합니다. 예: 문 열기, 조명 켜기, Collider 끄기, 플랫폼 활성화.
7. `On Deactivated`에는 체크포인트 복원이나 상태 초기화 때 되돌릴 동작을 연결합니다.
8. 테스트가 끝나면 실제 아트 색을 바꾸면 안 되는 오브젝트의 `Debug Color Feedback`은 끕니다.

예시:

```text
Future Locked Door
└─ Causal Receiver
   ├─ Causal Rule: SO_CR_P1_POWER_PANEL
   ├─ Receiver Effect: RCV_P1_SECURITY_DOOR (lockState=Unlocked)
   ├─ On Activated: DoorController.Open 또는 Collider2D.enabled = false
   └─ On Deactivated: DoorController.Close 또는 Collider2D.enabled = true
```

현재 `Causal Receiver`는 `State Value`가 비어 있지 않고 `Off`, `Locked`, `false`, `Inactive`가 아니면 활성화로 판단합니다. 예를 들어 `Unlocked`, `Powered`, `Open`, `Enabled`는 활성 상태로 처리됩니다.

### 3.9 Causality Manager 확인

Persistent 씬에는 활성화된 `Causality Manager`가 있어야 합니다. 인과가 작동하지 않을 때 가장 먼저 다음을 확인합니다.

1. Persistent 씬의 `Causality Manager`가 활성 상태인지 확인합니다.
2. `Causality Manager > Causal Rules` 배열에 사용할 모든 `CausalRuleSO`가 들어 있는지 확인합니다.
3. `Causal Trigger`와 `Causal Receiver`가 같은 `CausalRuleSO`를 바라보는지 확인합니다.
4. Play Mode Console에 `Trigger accepted`, `Trigger rejected`, `Receiver registry rebuilt` 로그가 나오는지 확인합니다.

Trigger와 Receiver에 SO를 연결했더라도 `Causality Manager > Causal Rules`에 빠져 있으면 Host 판정에서 규칙을 찾지 못합니다.

## 4. 연결 예시: 과거 차단기 패널이 미래 조명을 켜는 경우

### 4.1 CausalRuleSO

```text
SO_CR_P1_POWER_PANEL
  Rule Id: CR_P1_POWER_PANEL
  Trigger Id: TRG_P1_POWER_PANEL
  Required Role: Past
  Required Item Id: 비움
  Receiver Effects:
    [0] Receiver Id: RCV_P1_FUTURE_LIGHTS
        State Key: powerState
        State Value: Powered
  Interaction Weight: Major
```

### 4.2 과거 오브젝트

```text
Past Breaker Panel
├─ Layer: Interactable
├─ Circle Collider 2D
│  └─ Is Trigger: 켬
├─ Interactable Object
│  ├─ Item ID: SO_OBJ_P1_BREAKER_PANEL
│  ├─ Interaction Types: Examine, Operate
│  └─ Examine Text: 끊어진 회로를 다시 연결할 수 있을 것 같다.
└─ Causal Trigger
   └─ Causal Rule: SO_CR_P1_POWER_PANEL
```

### 4.3 미래 오브젝트

```text
Future Lights Root
└─ Causal Receiver
   ├─ Causal Rule: SO_CR_P1_POWER_PANEL
   ├─ Receiver ID: RCV_P1_FUTURE_LIGHTS
   ├─ On Activated: 조명 GameObject 활성화 또는 Light2D Intensity 증가
   └─ On Deactivated: 조명 GameObject 비활성화 또는 Light2D Intensity 초기화
```

### 4.4 Persistent 씬

```text
Causality Manager
└─ Causal Rules
   └─ SO_CR_P1_POWER_PANEL
```

## 5. Collider와 Layer 규칙

- `Interactable Object`가 붙은 GameObject에는 감지용 `Circle Collider 2D`가 있어야 합니다.
- 감지용 `Circle Collider 2D`의 `Is Trigger`는 켜져 있어야 합니다.
- 감지 Collider와 `Interactable Object`는 같은 GameObject에 둡니다.
- 대상 Layer는 플레이어 `Interaction Probe > Interactable Layers`에 포함되어야 합니다.
- `Project Settings > Physics 2D > Queries Hit Triggers`가 활성화되어야 합니다.
- 문처럼 통행을 막는 오브젝트는 감지용 Trigger Collider와 통행 차단용 비-Trigger Collider를 분리합니다.

문 오브젝트의 일반적인 구조:

```text
Door Interaction Object
├─ Circle Collider 2D: Trigger, 플레이어 상호작용 감지
├─ Interactable Object
└─ Door Operate Action
   └─ Target Door: Door Body

Door Body
├─ Animator
└─ Collider2D: 비-Trigger, 통행 차단
```

## 6. Play Mode 점검표

- [ ] `Interactable Object > Item ID`가 비어 있지 않습니다.
- [ ] 연결한 `ItemDefinitionSO.ItemId`가 기획서의 오브젝트/아이템 ID와 일치합니다.
- [ ] `Interaction Types`가 의도한 입력과 일치합니다.
- [ ] 감지 Collider와 `Interactable Object`가 같은 GameObject에 있습니다.
- [ ] 대상 Layer가 `Interaction Probe > Interactable Layers`에 포함됩니다.
- [ ] `Operate` 대상에 `Causal Trigger` 또는 하나 이상의 OperateAction이 있습니다.
- [ ] OperateAction은 `Interactable Object`와 같은 GameObject에 있습니다.
- [ ] 문 대상의 Animator에 bool 파라미터 `IsOpen`이 있습니다.
- [ ] 룸 전환의 `Destination`, `Target Room Id`, `Room Manager`가 올바릅니다.
- [ ] 퍼즐 UI 루트는 시작 시 비활성 상태입니다.
- [ ] `Causal Trigger`와 `Causal Receiver`가 같은 `CausalRuleSO`를 사용합니다.
- [ ] Persistent 씬의 `Causality Manager > Causal Rules`에 해당 `CausalRuleSO`가 포함됩니다.
- [ ] 다중 Receiver 규칙에서는 각 `Causal Receiver`의 `Receiver Effect` 선택이 올바릅니다.
- [ ] Play Mode에서 Console에 경고나 오류가 없습니다.

## 7. 문제 해결

### 하이라이트가 안 보입니다

- 대상 Layer가 `Interaction Probe > Interactable Layers`에 포함되어 있는지 확인합니다.
- 감지용 Collider의 `Is Trigger`가 켜져 있는지 확인합니다.
- `Project Settings > Physics 2D > Queries Hit Triggers`가 켜져 있는지 확인합니다.
- 마우스 hover 대상은 플레이어 상호작용 반경 안에 있어야 합니다.

### E를 눌러도 조작되지 않습니다

- `Interaction Types`에 `Operate`가 포함되어 있는지 확인합니다.
- `Required Item ID`가 있는 대상이면 먼저 올바른 아이템으로 우클릭해야 합니다.
- `Causal Trigger` 또는 OperateAction이 같은 GameObject에 붙어 있는지 확인합니다.
- `Operate interaction did not execute` 로그가 있으면 실행 컴포넌트 연결이 빠진 상태입니다.

### 아이템 사용이 실패합니다

- 플레이어가 아이템 슬롯 `1`~`5` 중 올바른 슬롯을 선택했는지 확인합니다.
- 대상의 `Required Item ID`와 선택 아이템의 `ItemId`가 일치하는지 확인합니다.
- 우클릭 대상은 플레이어 반경 안에 있고 마우스를 올린 상태여야 합니다.

### CausalTrigger는 실행됐는데 미래 오브젝트가 안 바뀝니다

- Persistent 씬에 활성화된 `Causality Manager`가 있는지 확인합니다.
- `Causality Manager > Causal Rules`에 해당 `CausalRuleSO`가 들어 있는지 확인합니다.
- `CausalTrigger`의 `Trigger ID`와 `CausalRuleSO.Trigger Id`가 일치하는지 확인합니다.
- `CausalReceiver`의 `Receiver ID`와 `CausalRuleSO.Receiver Effects`의 `Receiver Id`가 일치하는지 확인합니다.
- `Required Role`이 현재 플레이어 시간대와 맞는지 확인합니다. 보통 물리적 인과는 `Past → Future`입니다.
- Host Console의 `Trigger rejected` 로그에 거부 이유가 있는지 확인합니다.

### Receiver 색이 빨강/초록으로 바뀝니다

`Causal Receiver > Debug Color Feedback`이 켜져 있기 때문입니다. 테스트 확인용이면 유지하고, 실제 아트 색상을 보존해야 하는 오브젝트에서는 끕니다.

## 8. 현재 구현상 주의 사항

- `UseItem`은 `InteractableObject.RunInteraction()`에서 직접 실행되지 않고 `PlayerController`와 `InventoryController`가 처리합니다.
- 우클릭 아이템 사용 성공 후 대상이 `Operate`를 지원하면 `RunInteraction(Operate)`가 자동 호출됩니다.
- 인과 요청과 일반 OperateAction은 같은 `Operate`에서 함께 실행됩니다.
- 일반 OperateAction은 Host의 인과 승인 결과를 기다리지 않고 즉시 실행됩니다.
- Host 승인 후에만 적용해야 하는 문 개방, 통행 가능 상태, 진행 상태 변경은 `Causal Receiver`에서 처리합니다.
- `CausalReceiver`는 활성화/비활성화 이벤트만 호출합니다. 복잡한 상태 변경은 별도 어댑터 컴포넌트를 만들어 `On Activated`에 연결합니다.
- `RoomTransitionOperateAction`은 현재 로컬 이동 및 로컬 룸 보고 방식입니다.
- `PuzzleOperateAction`은 퍼즐 프레임워크가 아니라 UI 활성화용 진입점입니다.
- 상호작용 거리는 Transform 중심이 아니라 Collider의 최근접 지점부터 계산합니다.
