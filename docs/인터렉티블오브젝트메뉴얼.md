# 인터렉티블 오브젝트 Inspector 설정 매뉴얼

이 문서는 씬 오브젝트에 조사, 획득, 아이템 사용, 일반 조작, 인과 조작을 설정하는 방법을 설명한다.

관련 구현:

- `Caretaker/Assets/_Project/Scripts/World/InteractableObject.cs`
- `Caretaker/Assets/_Project/Scripts/World/IOperateAction.cs`
- `Caretaker/Assets/_Project/Scripts/World/DoorOperateAction.cs`
- `Caretaker/Assets/_Project/Scripts/World/RoomTransitionOperateAction.cs`
- `Caretaker/Assets/_Project/Scripts/World/PuzzleOperateAction.cs`
- `Caretaker/Assets/_Project/Scripts/World/CausalTrigger.cs`
- `Caretaker/Assets/_Project/Scripts/Gameplay/Player/InteractionProbe.cs`

## 1. 현재 실행 구조

```text
플레이어 입력
→ InteractionProbe가 플레이어 반경 안의 대상 선택
→ InteractionService 거리/타입 검증
→ InteractableObject.RunInteraction()
```

`InteractionProbe`는 플레이어 주변 반경 안에 들어온 모든 상호작용 가능 오브젝트에 하이라이트를 적용한다. 마우스 hover는 이 반경 안에 있는 오브젝트에 대해서만 유효하며, 범위 밖 오브젝트는 마우스를 올려도 후보가 되지 않는다.

`Operate`일 때는 다음 컴포넌트를 실행한다.

```text
InteractableObject.RunOperate()
├─ CausalTrigger가 있으면 Fire()
└─ 같은 GameObject의 모든 IOperateAction.Execute(actor)
```

따라서 하나의 조작으로 인과 요청과 일반 연출을 함께 실행할 수 있다. 예를 들어 레버에 `CausalTrigger`와 레버 애니메이션용 실행 컴포넌트를 함께 부착할 수 있다.

> 일반 액션은 `InteractableObject`와 같은 GameObject에 부착해야 한다. 현재 구현은 `GetComponents<IOperateAction>()`로 같은 GameObject의 컴포넌트만 수집한다.

아이템 사용은 별도 경로다.

```text
아이템 선택 후 우클릭
→ Required Item Id 검증
→ 아이템 사용/소모
→ 아이템 조건 충족 표시
→ 대상이 Operate를 지원하면 연결된 조작 실행
```

## 2. 기본 설정 순서

1. Hierarchy에서 상호작용 대상으로 만들 GameObject를 선택한다.
2. 대상 Layer를 플레이어 `Interaction Probe > Interactable Layers`에 포함된 Layer로 지정한다.
3. `Interactable Object`를 추가한다.
4. 자동 추가된 `Circle Collider 2D`의 크기와 위치를 조정한다.
5. `Object Id`에 `game-design.md`의 고유 ID를 입력한다.
6. `Interaction Types`에서 필요한 타입을 선택한다.
7. 조사, 획득, 아이템 조건에 필요한 필드를 입력한다.
8. `Operate` 대상이면 같은 GameObject에 실행 컴포넌트(OperateAction) 또는 `Causal Trigger`를 추가한다.
9. Play Mode에서 입력, 거리, 실행 결과와 Console을 확인한다.

> 감지용 Collider와 `Interactable Object`는 같은 GameObject에 두어야 한다. 현재 감지 코드는 Collider가 붙은 GameObject에서 직접 `InteractableObject`를 찾는다.

## 3. Interactable Object 필드

### Object Identity

| 필드 | 설정 방법 |
| --- | --- |
| `Object Id` | 오브젝트마다 겹치지 않는 ID를 입력한다. 예: `OBJ_P1_DOOR_BTN` |
| `Interaction Types` | 지원할 타입을 선택한다. 여러 타입을 함께 선택할 수 있다. |

### Interaction

| 필드 | 설정 방법 |
| --- | --- |
| `Required Item Id` | 우클릭 아이템 사용에 필요한 아이템 ID. 필요 없으면 비운다. |
| `Granted Item Id` | `Acquire` 성공 시 인벤토리에 추가할 아이템 ID. |
| `Examine Text` | `Examine` 성공 시 팝업 본문에 표시할 설명. |
| `Examine Image` | 조사 팝업에 선택적으로 표시할 `Sprite`. 비워 두면 텍스트 영역이 전체 폭을 사용한다. |

### Highlight

| 필드 | 설정 방법 |
| --- | --- |
| `Outline Behaviours` | 하이라이트 시 활성화할 아웃라인 또는 강조 효과 컴포넌트 배열. |
| `Use Fallback Glow` | 별도 아웃라인 컴포넌트가 없어도 자식 `SpriteRenderer`를 복제한 반투명 glow 레이어를 자동 생성한다. |
| `Fallback Glow Color` | 자동 glow 레이어의 색상과 투명도. |
| `Fallback Glow Scale` | 자동 glow 레이어의 확대 비율. |
| `Fallback Glow Sorting Order Offset` | 원본 `SpriteRenderer` 대비 자동 glow 레이어의 정렬 순서 보정값. |
| `Highlight On Awake` | 시작부터 하이라이트가 필요한 경우에만 선택한다. |

## 4. Interaction Types와 입력

| 타입 | 입력 | 용도 |
| --- | --- | --- |
| `Examine` | 반경 1 unit 안에서 좌클릭 | 안내판, CCTV, 책장, 잠긴 문 조사 |
| `Acquire` | 반경 1 unit 안에서 좌클릭 | 신문, 배터리, 케이블 등 획득 |
| `Operate` | 반경 1 unit 안에서 `E` | 문, 버튼, 레버, 엘리베이터, 계단 등 물리적 조작 |
| `Use Item` | 아이템 선택 후 근접 대상에서 우클릭 | `Required Item Id` 조건 충족 |

근접 하이라이트는 반경 안의 모든 상호작용 가능 오브젝트에 적용된다. E키용 근접 후보는 조건을 만족한 `Operate` 대상 중 가까운 대상이다.
입력별 실행 타입은 다르다.

- 좌클릭: 반경 안에서 마우스를 올린 대상이 `Acquire` 가능 대상이면 획득, 아니면 `Examine`.
- 우클릭: 반경 안에서 마우스를 올린 `Required Item Id` 미충족 대상에 선택 아이템 사용.
- `E`: `Operate`만 실행. 획득은 실행하지 않는다.

Tab 키는 일반 모드와 전투 모드를 전환한다. 일반 모드에서 좌클릭/우클릭은 상호작용으로 처리되고, 전투 모드에서 좌클릭/우클릭은 전투 시스템의 공격/조준 입력으로 예약된다.

프롬프트 표시 기준:

- `Operate` 전용 오브젝트: 플레이어가 반경 안에 접근하면 E 프롬프트가 표시된다.
- `Examine`, `Acquire`, `Use Item` 대상: 플레이어가 반경 안에 있고 마우스를 올린 경우에만 좌클릭/우클릭 프롬프트가 표시된다.

`Use Item`은 `InteractableObject.RunInteraction()`에서 직접 실행되지 않는다. `Required Item Id`가 설정된 근접 대상을 `PlayerController`와 `InventoryController`가 처리한다.

## 5. 기본 유형 설정

### 조사 오브젝트

```text
Interactable Object
  Object Id: OBJ_P1_CCTV
  Interaction Types: Examine
  Required Item Id: 비움
  Granted Item Id: 비움
  Examine Text: 엘리베이터가 작동하지 않는다.
```

### 획득 아이템

```text
Interactable Object
  Object Id: OBJ_P1_BATTERY
  Interaction Types: Acquire
  Granted Item Id: ITEM_BATTERY
```

`Granted Item Id`와 같은 ID를 가진 `ItemDefinitionSO`가 플레이어의 `Inventory Controller > Item Definitions`에 등록되어 있어야 한다.

### 아이템이 필요한 오브젝트

```text
Interactable Object
  Object Id: OBJ_P2_CARD_READER
  Interaction Types: Operate
  Required Item Id: ITEM_KEY_CARD
  Examine Text: 카드키가 필요하다.
```

동작 순서:

1. 슬롯 키 `1`~`5`로 아이템을 선택한다.
2. 대상 반경 안에서 우클릭한다.
3. 아이템 ID가 일치하면 아이템을 사용하고 조건을 충족 상태로 표시한다.
4. 대상이 `Operate`를 지원하면 연결된 일반 실행 컴포넌트를 즉시 실행한다.

대상에 `CausalTrigger`가 함께 붙어 있으면 우클릭 아이템 사용 성공 후 `Operate` 경로를 통해 인과 요청도 발생할 수 있다. 아이템 사용만으로 인과 요청이 발생하면 안 되는 대상은 `CausalTrigger`를 별도 오브젝트로 분리한다.

## 6. 일반 Operate 실행 컴포넌트

World/OperateAction 폴더에 있는 실행 컴포넌트들을 사용한다.
일반 조작은 `IOperateAction`을 구현한 컴포넌트로 구성한다. `InteractableObject`는 같은 GameObject에 붙은 모든 실행 컴포넌트를 캐시하고 순서대로 호출한다.
`DoorOperateAction`, `RoomTransitionOperateAction`, `PuzzleOperateAction`은 같은 GameObject의 `InteractableObject`에 `Operate` 타입을 자동으로 포함시킨다. 그래도 Inspector에서 `Interaction Types`에 `Operate`가 보이는지 확인하면 설정 상태를 빠르게 점검할 수 있다.

현재 제공하는 실행 컴포넌트:

| 컴포넌트 | 용도 |
| --- | --- |
| `Door Operate Action` | 문 Animator 실행과 통행 Collider 비활성화 |
| `Room Transition Operate Action` | 계단/엘리베이터의 목표 위치 이동 |
| `Puzzle Operate Action` | 퍼즐 UI 루트 활성화 |

`Operate`를 선택했지만 `CausalTrigger`와 `IOperateAction`이 모두 없으면 상호작용은 실패한다.
`RoomTransitionOperateAction`은 `Destination`이 비어 있거나 실행할 플레이어가 없으면 Console에 실패 원인을 출력한다.

### 문 또는 문 버튼

직접 조작하는 문:

```text
Door Interaction
├─ Interactable Object
│  └─ Interaction Types: Operate
└─ Door Operate Action
   └─ Target Door: 실제 문 GameObject
```

문 버튼도 같은 방식으로 설정하되 `Target Door`에 버튼이 열 문 GameObject를 연결한다.

`Door Operate Action`은 대상 문과 자식에서 다음 컴포넌트를 찾는다.

- `Animator`: bool 파라미터 `IsOpen`을 `true`로 변경
- 첫 번째 비-Trigger `Collider2D`: 문이 열릴 때 비활성화

현재 문 오브젝트에는 통행을 막는 비-Trigger Collider를 하나만 두는 것을 전제로 한다. 대상 문이 비어 있으면 실행에 실패한다.

### 계단 또는 엘리베이터

```text
Interactable Object
  Interaction Types: Operate

Room Transition Operate Action
  Destination: 도착 위치 Transform
  Target Room Id: 도착 룸 ID
  Room Manager: Persistent 씬의 RoomManager
```

실행 시 플레이어의 Rigidbody 속도를 초기화하고 `Destination` 위치로 이동한다. `RoomManager`, `Target Room Id`, `RoomParticipant`가 모두 유효하면 룸 진입 상태도 보고한다.

> 현재 이동과 룸 보고는 로컬 실행이다. Host 권위 네트워크 전환은 후속 네트워크 통합 대상이다.

### 퍼즐 장치

```text
Interactable Object
  Interaction Types: Operate

Puzzle Operate Action
  Puzzle Root: 비활성 상태로 시작하는 퍼즐 UI 루트
  On Puzzle Opened: 선택 사항
  On Puzzle Closed: 선택 사항
```

`Execute()`는 `Puzzle Root`를 활성화한다. 닫기 버튼의 `OnClick`에는 `PuzzleOperateAction.Close()`를 연결한다.

현재 컴포넌트는 퍼즐 UI 활성화와 닫기 이벤트만 담당한다. 플레이어 입력 잠금, 커서, 퍼즐 성공/실패, 네트워크 판정은 후속 퍼즐 프레임워크에서 처리한다.

## 7. 인과 조작

1. `Interactable Object > Interaction Types`에 `Operate`를 포함한다.
2. 같은 GameObject에 `Causal Trigger`를 추가한다.
3. `Causal Trigger > Causal Rule`에 `CausalRuleSO`를 연결한다.
4. `Trigger Id`가 규칙에서 자동 입력되었는지 확인한다.
5. Persistent 씬에 활성화된 `Causality Manager`가 있는지 확인한다.

```text
Interactable Object
  Object Id: OBJ_P1_BREAKER_PANEL
  Interaction Types: Examine, Operate

Causal Trigger
  Causal Rule: SO_CR_P1_POWER_PANEL
```

인과 조작에 로컬 애니메이션이나 효과가 필요하면 같은 GameObject에 `IOperateAction` 구현 컴포넌트를 함께 붙인다.

```text
Operate 실행
├─ CausalTrigger.Fire()
└─ 모든 IOperateAction.Execute()
```

현재 일반 액션은 Host의 인과 승인 결과를 기다리지 않고 즉시 실행된다. 따라서 `IOperateAction`에는 레버 애니메이션처럼 요청 즉시 보여도 되는 로컬 표현을 연결한다. Host 승인 후에만 적용해야 하는 문 개방이나 진행 상태 변경은 인과 Receiver에서 처리한다.

## 8. Collider와 Layer

- `Interactable Object`를 추가하면 `Circle Collider 2D`가 자동 추가된다.
- 감지 Collider의 `Is Trigger`는 자동 활성화된다.
- `Radius`와 `Offset`을 클릭 및 접근 영역에 맞춘다.
- 감지 Collider와 `Interactable Object`는 같은 GameObject에 둔다.
- 대상 Layer가 `Interaction Probe > Interactable Layers`에 포함되어야 한다.
- `Project Settings > Physics 2D > Queries Hit Triggers`가 활성화되어야 한다.

문에는 두 종류의 Collider가 있을 수 있다.

- 상호작용 오브젝트의 `Circle Collider 2D`: Trigger
- 실제 문의 통행 차단 `Collider2D`: 비-Trigger

## 9. Play Mode 점검표

- [ ] `Object Id`가 비어 있지 않고 중복되지 않는다.
- [ ] `Interaction Types`가 의도한 동작과 일치한다.
- [ ] 감지 Collider와 `Interactable Object`가 같은 GameObject에 있다.
- [ ] 대상 Layer가 `Interactable Layers`에 포함된다.
- [ ] `Operate` 대상에 `CausalTrigger` 또는 하나 이상의 `IOperateAction`이 있다.
- [ ] 일반 실행 컴포넌트가 `Interactable Object`와 같은 GameObject에 있다.
- [ ] 문 대상의 Animator에 bool 파라미터 `IsOpen`이 있다.
- [ ] 룸 전환의 `Destination`과 `Target Room Id`가 올바르다.
- [ ] 퍼즐 UI 루트가 시작 시 비활성 상태다.
- [ ] 인과 대상의 `CausalRuleSO`와 `Causality Manager`가 연결되어 있다.
- [ ] Console에 경고나 오류가 발생하지 않는다.

## 10. 현재 구현상 주의 사항

- `Examine` 결과는 로컬 플레이어의 전용 팝업에 `Object Id`, `Examine Text`, 선택적 `Examine Image`로 표시된다.
- 조사 팝업은 닫기 버튼, `ESC`, `E`로 닫으며 열려 있는 동안 게임플레이 입력과 상호작용 하이라이트를 잠근다.
- 우클릭 아이템 사용 성공 후 대상이 `Operate`를 지원하면 `RunInteraction(Operate)`가 호출된다.
- 인과 요청과 일반 `IOperateAction`은 같은 `Operate`에서 함께 실행된다.
- 인과 요청의 실제 Host 승인 전에 일반 액션이 실행될 수 있다.
- `DoorOperateAction`의 열림 상태는 액션 컴포넌트에 저장된다.
- `RoomTransitionOperateAction`은 현재 로컬 이동 및 로컬 룸 보고 방식이다.
- `PuzzleOperateAction`은 퍼즐 프레임워크가 아니라 UI 활성화용 임시 진입점이다.
- 상호작용 거리는 Transform 중심이 아니라 Collider의 최근접 지점부터 계산한다.
