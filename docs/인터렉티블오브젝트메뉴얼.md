# 인터렉티블 오브젝트 Inspector 설정 매뉴얼

이 문서는 씬의 오브젝트를 플레이어가 조사하거나, 획득하거나, 가까이서 조작할 수 있도록 만드는 방법을 설명한다.

관련 구현:

- `Caretaker/Assets/_Project/Scripts/World/InteractableObject.cs`
- `Caretaker/Assets/_Project/Scripts/Gameplay/Player/InteractionProbe.cs`
- `Caretaker/Assets/_Project/Scripts/World/CausalTrigger.cs`

## 1. 가장 빠른 설정 순서

1. Hierarchy에서 상호작용 대상으로 만들 GameObject를 선택한다.
2. 오브젝트의 위치와 Sprite Renderer 등 기본 표시 상태를 설정한다.
3. Inspector의 **Layer**를 플레이어 `Interaction Probe > Interactable Layers`에 포함된 Layer로 지정한다.
4. **Add Component**에서 `Interactable Object`를 추가한다.
5. 자동으로 추가된 `Circle Collider 2D`의 크기와 위치를 오브젝트 모양에 맞춘다.
6. `Interactable Object`의 `Object Id`에 고유 ID를 입력한다.
7. `Interaction Types`에서 필요한 상호작용 종류를 선택한다.
8. 선택한 종류에 따라 `Required Item Id`, `Granted Item Id`, `Examine Text`를 입력한다.
9. 하이라이트 효과가 있다면 `Outline Behaviours`에 해당 컴포넌트를 연결한다.
10. Play Mode에서 거리, 입력, 하이라이트와 Console 로그를 확인한다.

> `Interactable Object`와 감지용 `Collider 2D`는 같은 GameObject에 두어야 한다. 현재 감지 코드는 Collider가 붙은 GameObject에서 직접 `Interactable Object`를 찾는다.

## 2. Interactable Object 필드

### Object Identity

| 필드 | 설정 방법 |
| --- | --- |
| `Object Id` | 오브젝트마다 겹치지 않는 ID를 입력한다. `game-design.md`의 ID를 사용한다. 예: `OBJ_P1_SIGN` |
| `Interaction Types` | 지원할 동작을 하나 이상 선택한다. 여러 종류를 함께 선택할 수 있다. |

### Interaction

| 필드 | 설정 방법 |
| --- | --- |
| `Required Item Id` | 상호작용 전에 필요한 아이템 ID. 필요 없으면 비워 둔다. 예: `ITEM_KEY_CARD` |
| `Granted Item Id` | 획득 시 플레이어 인벤토리에 추가할 아이템 ID. 획득 오브젝트가 아니면 비워 둔다. |
| `Examine Text` | 조사했을 때 보여 줄 설명. 현재 구현에서는 Console 로그로 출력된다. |

### Highlight

| 필드 | 설정 방법 |
| --- | --- |
| `Outline Behaviours` | 하이라이트 시 켜고 끌 `Behaviour` 컴포넌트를 배열에 등록한다. 아웃라인 또는 별도 강조 효과 컴포넌트를 드래그한다. |
| `Highlight On Awake` | 게임 시작부터 하이라이트를 켜야 할 때만 체크한다. 일반 오브젝트는 해제한다. |

## 3. Interaction Types와 입력

| 타입 | 플레이어 입력 | 용도 |
| --- | --- | --- |
| `Examine` | 대상에 마우스를 올리고 좌클릭 | 안내판, CCTV, 책장처럼 정보를 조사한다. |
| `Acquire` | 반경 1 unit 안에서 상호작용 키 `E` | 배터리, 케이블, 카드키 같은 아이템을 획득한다. |
| `Operate` | 반경 1 unit 안에서 상호작용 키 `E` | 문, 버튼, 레버, 장치를 조작한다. |
| `Use Item` | 아이템 선택 후 대상 가까이에서 우클릭 | `Required Item Id`가 있는 대상에 선택 아이템을 사용한다. |

근접 후보가 여러 개면 현재 우선순위는 `Acquire` → `Use Item` → `Operate` → `Examine`이며, 같은 우선순위에서는 더 가까운 대상이 선택된다.

> 우클릭은 현재 마우스가 가리키는 대상이 아니라 플레이어에게 가장 가까운 근접 대상을 사용한다.

## 4. 유형별 Inspector 예시

### 조사만 가능한 오브젝트

안내판이나 책장처럼 내용을 확인하는 대상이다.

```text
Object Id: OBJ_P1_SIGN
Interaction Types: Examine
Required Item Id: 비움
Granted Item Id: 비움
Examine Text: 변전실은 지하 1층에 있다.
```

`Circle Collider 2D`를 이미지 전체에 맞춘다. 조사는 마우스 포인터 Raycast로 감지되므로 Collider 영역이 너무 작지 않아야 한다.

### 획득 가능한 아이템

배터리나 카드키처럼 인벤토리에 들어가는 대상이다.

```text
Object Id: OBJ_P1_BATTERY
Interaction Types: Acquire
Required Item Id: 비움
Granted Item Id: ITEM_BATTERY
Examine Text: 예비 배터리다.
```

추가 확인 사항:

1. `Granted Item Id`와 같은 ID를 가진 `ItemDefinitionSO` 에셋이 있어야 한다.
2. 해당 `ItemDefinitionSO`가 플레이어의 `Inventory Controller > Item Definitions`에 등록되어 있어야 한다.
3. 정상 획득 후 같은 오브젝트에서는 다시 획득할 수 없다.

조사와 획득을 모두 지원하려면 `Interaction Types`에서 `Examine`과 `Acquire`를 함께 선택한다.

### 일반 조작 오브젝트

문, 버튼, 레버처럼 가까이에서 `E`로 사용하는 대상이다.

```text
Object Id: OBJ_P1_DOOR_BTN
Interaction Types: Operate
Required Item Id: 비움
Granted Item Id: 비움
Examine Text: 비움 또는 설명 입력
```

현재 인과 트리거가 없는 `Operate`는 성공 로그만 출력한다. 문 열기, 애니메이션, 사운드 같은 실제 반응은 별도 동작 컴포넌트와 연결하는 구현이 추가로 필요하다.

### 아이템이 필요한 오브젝트

카드 리더나 수리 장치처럼 특정 아이템을 먼저 사용해야 하는 대상이다.

```text
Object Id: OBJ_P2_ARCHIVE_READER
Interaction Types: Operate
Required Item Id: ITEM_KEY_CARD
Granted Item Id: 비움
Examine Text: 카드키가 필요하다.
```

설정 후 동작 순서:

1. 플레이어가 인벤토리 슬롯 키 `1`~`5`로 필요한 아이템을 선택한다.
2. 대상의 1 unit 안에서 우클릭한다.
3. ID가 일치하면 아이템 조건이 충족된다.
4. 이후 대상은 `Operate` 등 다음 근접 상호작용을 받을 수 있다.

`Interaction Types`의 `Use Item` 체크 여부만으로 아이템 사용 대상을 만들 수는 없다. 현재 구현은 `Required Item Id`가 비어 있지 않은지를 기준으로 아이템 사용 대상을 판정한다.

### 과거에서 미래에 영향을 주는 인과 오브젝트

1. 먼저 위의 일반 조작 오브젝트처럼 `Interactable Object`를 설정한다.
2. `Interaction Types`에 `Operate`를 포함한다.
3. 같은 GameObject에 `Causal Trigger`를 추가한다.
4. `Causal Trigger > Causal Rule`에 사용할 `CausalRuleSO` 에셋을 드래그한다.
5. `Trigger Id`가 에셋 값으로 자동 입력되었는지 확인한다.
6. 씬에 활성화된 `Causality Manager`가 있는지 확인한다.

```text
Interactable Object
  Object Id: OBJ_P1_BREAKER_PANEL
  Interaction Types: Examine, Operate

Causal Trigger
  Causal Rule: SO_CR_P1_POWER_PANEL
  Trigger Id: CausalRuleSO에서 자동 입력
```

`CausalRuleSO`의 `Trigger Id`와 연결될 Receiver 설정은 `docs/design/DSD.md`의 시간 인과 시스템 항목을 따른다.

## 5. Collider와 Layer 설정

### Collider

- `Interactable Object`를 추가하면 `Circle Collider 2D`가 자동으로 추가된다.
- Collider의 `Is Trigger`는 컴포넌트가 자동으로 활성화한다.
- `Radius`와 `Offset`을 오브젝트의 실제 클릭 및 접근 영역에 맞춘다.
- 자식 오브젝트에 Collider를 따로 두는 구조는 현재 감지되지 않는다.
- Collider를 추가로 사용할 수 있지만, 감지할 Collider와 `Interactable Object`는 같은 GameObject에 있어야 한다.

### Layer

- 대상 GameObject의 Layer가 플레이어 `Interaction Probe > Interactable Layers`에 포함되어야 한다.
- 감지되지 않으면 대상 Layer와 `NetworkPlayer` 프리팹의 `Interaction Probe` Layer Mask를 함께 확인한다.
- `Project Settings > Physics 2D > Queries Hit Triggers`가 활성화되어 있어야 근접 Trigger Collider를 감지한다.

## 6. 하이라이트 연결

1. 대상에 아웃라인이나 강조 효과를 담당하는 `Behaviour` 컴포넌트를 추가한다.
2. 해당 컴포넌트는 기본 상태에서 비활성화한다.
3. `Interactable Object > Outline Behaviours`의 Size를 필요한 개수로 늘린다.
4. 각 Element에 효과 컴포넌트를 드래그한다.
5. Play Mode에서 마우스 hover 또는 1 unit 접근 시 효과가 켜지는지 확인한다.

`Sprite Renderer` 자체를 배열에 넣으면 하이라이트 시 렌더러 전체가 켜지고 꺼지므로, 일반적으로 별도의 아웃라인 컴포넌트를 연결한다.

## 7. Play Mode 점검표

- [ ] `Object Id`가 비어 있지 않고 다른 오브젝트와 중복되지 않는다.
- [ ] `Interaction Types`가 의도한 동작과 일치한다.
- [ ] Collider 크기와 Offset이 오브젝트 모양에 맞는다.
- [ ] Collider와 `Interactable Object`가 같은 GameObject에 있다.
- [ ] 대상 Layer가 `Interactable Layers`에 포함된다.
- [ ] 조사 대상은 마우스 hover와 좌클릭에 반응한다.
- [ ] 근접 대상은 플레이어와 Collider 사이 거리가 1 unit 이내일 때 `E`에 반응한다.
- [ ] 획득 대상의 `Granted Item Id`가 `ItemDefinitionSO`와 정확히 일치한다.
- [ ] 아이템 요구 대상의 `Required Item Id`가 `ItemDefinitionSO.Item Id`와 정확히 일치한다.
- [ ] 인과 대상은 `Causal Trigger`, `CausalRuleSO`, `Causality Manager`가 모두 연결되어 있다.
- [ ] Console에 경고나 오류가 발생하지 않는다.

## 8. 현재 구현상 주의 사항

- `Examine` 결과는 아직 전용 정보 UI가 아니라 Console 로그로 출력된다.
- 인과가 아닌 `Operate`는 실제 문이나 레버 상태를 바꾸지 않고 Console 로그만 출력한다.
- 아이템 우클릭은 포인터 위치보다 근접 후보를 사용한다.
- 상호작용 거리는 Transform 중심이 아니라 Collider의 최근접 지점부터 계산한다.
- `Use Item`은 `InteractableObject.RunInteraction()`에서 직접 실행되는 타입이 아니다. 아이템 요구 조건은 반드시 `Required Item Id`로 설정한다.
